# `apps/core`

What this app holds and how its parts fit. Loaded when you work in this directory; the
rules that hold everywhere are in the root `CLAUDE.md`. Keep this file current when the
app changes.

## Layout

- `BaseModel`, security cache, checks, middleware, the read-only admin base (`ReadOnlyModelAdmin`, `READ_ONLY_METHODS`)
- `sequences` (`next_number`)
- `idempotency`
- `locking` (L0-L9, `LockOrder`, `run_in_transaction`/`@transactional`, advisory locks)
- `events`
- `fields` (quantity/price presets)
- `migration_ops` (composite FKs; `on_update="CASCADE"` for a denormalized key children follow)
- `commands` (`OperatorCommand`; `also_capabilities` + `principal_for` for a command that spans domains)
- `tabular` (CSV/XLSX reader)
- `imports` (`ImportCommand`: report, one transaction per file, `--dry-run`)
- `demo` + `manage seed_demo`
- `changes` (`apply_changes`)
- `db` (`db_now`, `db_clock`)
- `stats` (M8b.5: `Calendar` of a period's weeks, `weekly`/`weekly_by`/`weekly_aggregate` counted in SQL by `TruncWeek` in `TIME_ZONE`, `Median`/`median_duration`, `top`)
- `forms` (`IdempotentForm`, `ValidityForm`, service errors)
- `responses` (409/400 answers, `perform`/`invalid` for a POST-only action's flash and redirect (`perform`'s flash and place may be functions of what the service returned, with `failed_to` for a refusal: a create lands on what it made; `also` for flashes that follow the success, M14.4); M8b.3's dialog contract: `go` (redirect, or 204 + `HX-Redirect` to htmx, plus `HX-Refresh: true` when the URL has a fragment and is the page posted from (`HX-Current-URL`): a fragment-only change loads nothing, M14.2), `Dialog` (a form shown again in its dialog: 422 with its errors), the 409 fragment `components/dialog_problem.html`, `varies`)
- `dialogs` (M8b.4: `ActionDialog`, one object that says what a page's action dialog shows (title, consequences, warning, form, where it posts, tone; M10.2: a `body` template drawn under the fields with `data`, a function called only when drawn) and is drawn by `components/action_dialog.html` and rebuilt around the bound form by the POST view (`spec.dialog()`, so the 422 shows the same markup); `lazy` answers the fragment of a row's shared lazy dialog to htmx and `layouts/dialog_page.html` otherwise (a GET-only URL, matrix rows with their htmx variants); a page with rows per line, allocation or dispatch keys its dialog and field ids by them; `docs/design/dialog-inventory.md` says how every former `<details>` form opens now)
- `idempotency.recorded_result` (what a key already produced: a form no longer valid after a double tap leads to that document)
- `http` (`client_ip`, `is_htmx`: false for an htmx history-restore request)
- `listing` (M7d.1: `paginate`/`ListPage`/`render_list`, `PAGE_SIZES` 10/25/50/100, `?page=`, `?per_page=`, `?sort=` from a per-list allowlist, invalid values fall back to the defaults, the primary key is the tie-breaker; components `pagination`, `list_toolbar`, `list_summary`, `sort_header`, tags in `list_tags` (`page_url`, `clear_filters_url`); M7d.3: `ListScope` (prefix, anchor, fixed size) renames the three parameters for a section of a page with several lists, `by_revocation`/`OPEN_FIRST` for lists of revoked grants; M7d.4: `cursor_page`/`CursorPage` (`?after=<key of the row the page follows>`, `?back=` the pages before, `cursor_pagination.html`, `{% cursor_url %}`), `head` for lists and counts worked out a stretch at a time, and `seek_after`/`after_q` (keyset seek: `WHERE (order) > (anchor) ORDER BY … LIMIT n`))
- `preferences` (M8b.2: the `__Host-ui` display cookie, a fixed grammar of allowlisted tokens for the theme, the hidden menu and folded categories; `PreferencesForm`, `parse`; written only by `views.ui_preferences` at `/ui/preferences/`, POST only, open to signed-out visitors, no service, no audit; the context processor `preferences` turns it into `ui_theme`/`ui_menu_hidden`/`ui_folded`, never the text)
- `navigation` (M8b.2: the menu's categories and entries defined once, `{% app_navigation as nav %}` in `nav_tags`: groups, the phone bar of four, the More sheet, the current page; an entry only with its capability; M10.2: the *Administration* category (People, Companies, Branches, `org.manage`), a key in `preferences.CATEGORY_KEYS`)

## Lists in detail (the root `CLAUDE.md`'s Conventions keep the rules)

every list view pages through `apps.core.listing` (`paginate` + `render_list`, the toolbar/summary/pager components, filters from selectors; page size, sort and page live in the URL only). Bounded document lists are the exceptions (plan Q43): lines of a request, order, receipt or handover, the attachments panel, dashboard panels, the catalog picker. A list view that bypasses it needs a reason in the PR. A page with several lists (a project's assignments, a person's roles, shared projects and invitations, the purchasing worklist's drafts and ordered-for-nobody) gives each section a `ListScope` (`assignments_page`, `drafts_page`, …), a prefixed filter form (`assignments-state`) and `list_toolbar.html` with `scoped=True` and `select=` (htmx takes the section out of the full page; no extra URL), inside a `data-list-section`; ticks of the worklist builder count for the page shown (plan Q41). **Every list reads only what it shows:** the database pages it (`LIMIT`), never Python after loading the whole set. A list whose rows are worked out from the ledger (the purchasing worklist and its ordered-for-nobody section, a project's materials, its expected deliveries) is read from a cursor instead (`cursor_page`, `CursorPage`, `components/cursor_pagination.html`; plan Q40): a source's `seek(cursor, n)` reads the next `n` candidate keys from the database in the list's order (`seek_after`: the order's fields annotated, never NULL, primary key last; the cursor's anchor read without the list's filters, so a row that left the list still marks its place), and its `window` works out the rows of that stretch only, so a page costs the page, not the backlog; its order and filters are SQL-able (a derived quantity can drop rows in the `window`, never order them); First / Previous / Next, no total, and the dashboard counts built the same way stop at "99+" (`head`). Such a list must give the rows of the eager `to_purchase` / `unallocated_on_order` / `expected_deliveries` page after page (tested on the volume dataset). **Budget (M7d.4):** every list answers in at most 300 ms of server time on `tests/volume.py`'s dataset (100k audit events, 20k materials, 10k requests with 50k lines, 5k orders, 5k receipts, 2k handovers) and costs the same number of queries at 10 and at 100 rows (`tests/integration/test_list_volume.py`, best of 5; a new list or panel gets a `Screen` there). A list whose every row is a heavy card (My requests, the worklist) caps its sizes with `ListScope(max_per_page=…)` (50, the worklist 25); `{% chip %}` (`ui_tags`) replaces the chip include on rows drawn by the hundred. `templates/django/forms/widgets/select.html` writes a select's options in place (same markup as Django's, no include per option: a filter with hundreds of projects or suppliers).
