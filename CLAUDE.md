# gmat-m8

Materials app for any company, or group of companies with branches, that buys for its projects and worksites: technicians request materials for worksites, managers approve, purchasing orders from suppliers, goods are received at a warehouse or on site and handed over. Modular Django monolith (Django 6.1 + HTMX + PostgreSQL 18), Docker Compose on one VPS.

## Source of truth

- **Plans:** markdown files in `.plans/todo/`; there can be several. Work from the plan the maintainer names; "plan §n" in this file means a section of that plan. Plans are local and git-ignored (missing in clones, CI and cloud sessions). If the named plan is missing, or none is named and the choice is unclear, stop and ask; never work from memory of a plan. Before a phase, read the plan's working rules, the phase's step cards and the sections they list.
- **Decisions:** the plan's decisions and answered questions; committed ones live in `docs/adr/` (from M1.1 on), and an ADR wins over any plan. **Keep them true (ADR-0026):** each ADR names the files it governs (`- **Governs:**`); a change that alters, extends or contradicts a recorded decision updates or supersedes its ADR in the same PR, a new decision gets a new ADR, and every PR touching a governed file names each such ADR in its `## ADRs` section ("updated" or "checked, still holds because …"). `python scripts/check_adr_alignment.py which <path>` lists them; the edit hook and the `adr-alignment` check enforce it. For a question still open, use its working assumption and say so in the PR. Do not invent business rules.
- Keep this file current when commands, layout or rules change.

## Git, PRs, releases

- **One phase = one branch = one PR** (M1, M2, …). Branch: `git switch --no-track -c m<phase>-<slug> origin/main` (e.g. `m2-org-access`). Human steps (`H*`) are skipped. Commit per step with Conventional Commits + step id: `feat(access): resolve dependent branch scope [M2.3]`. Never `--no-verify`.
- **Release ordering (plan §0.2):** a step that publishes or releases (M1.7 `docker-publish.yaml`) never shares a PR with the code it builds. Open and merge the preceding PR first (M1: PR 1 = M1.1–M1.6 on `m1-foundation`), then cut `m1-release` from the updated `origin/main` for M1.7 in its own PR. Nothing is tagged, released or published before both are merged and H1.8 is done.
- Agents use the configured owner account (`gh`/git): commit, `git push -u origin <branch>`, open the PR with `gh pr create --repo mano8/gmat-m8 --head <branch> --draft`, answer reviews.
- **Never:** merge or approve a PR; push to `main` or force-push; create tags or GitHub Releases (`v*` tags publish images); run `gh workflow run` or `docker-publish`; deploy or touch production data; change repo settings, rulesets, secrets or tokens. GitHub will not stop the owner account, so these rules and `.claude/settings.json` are the guard.
- **No attribution:** no `Co-Authored-By` lines, no "Generated with" footers and no AI tool or model names in commits, PR titles, descriptions or comments.
- When a step's job is done (implemented with tests, committed, pushed, local gates green), tick its box in the plan's TODO list and note anything only the phase PR can settle. Mark the PR ready only when CI is green and every step's review gate (R1/R2/R3, see the plan's review legend) has run and been addressed. Then append `· PR #n` to each of the phase's step lines. The human merges the PR at the end of the phase.
- **Merge method: merge commit, never squash or rebase** (Dependabot PRs too). `main` keeps every step commit (`git log --first-parent main` gives one line per PR) and `git branch --merged origin/main` stays reliable for cleaning up branches. Branches merged before this rule were squashed: git cannot tell they are merged, so check the PR before deleting one.
- Never stage `.plans/` or use `git add -f`. Never commit secrets or real env files (`.env`, `*.env`, backups, keys); only `*.example` templates.
- Workflows: never `pull_request_target` or `workflow_run`, never a PR check that needs a secret (`coverage-upload` is the one job that reads repository secrets, `CODECOV_TOKEN` and `CODACY_PROJECT_TOKEN`: not required, runs none of the project's code, skips a service it has no token for), never `on.paths` on a required workflow (scope job + always-running gate job, plan §8.4). Flag any `.github/workflows/` change for explicit review.

## Architecture invariants

**Layers.** Views read via `selectors.py` and write via `services.py`, never models directly. Services never import views, forms or the request; they take a **principal** (`SessionPrincipal`, `TokenPrincipal` one operation, `SystemPrincipal` worker without business capability, `OperatorPrincipal` for commands with `--operator <email>`) and check capabilities themselves. Only allowlisted modules construct non-session principals.

**Access** (`apps/access`, plan §3):

- Scoped models only via `visible_to(ctx, capability)` or selectors; no bare `Model.objects` in views, forms, template tags; form choice querysets come from selectors.
- Capabilities from `ROLE_CAPABILITIES`, never mixed across memberships: `ctx.scope_for(capability)`.
- Roles: `GROUP_ADMIN`, `MATERIAL_MANAGER`, `ENGINEER` (privileged, branch-level; ranks below `GROUP_ADMIN` and above every other role: every material-manager capability; ADR-0014), `WAREHOUSE_OPERATOR`, `TECHNICIAN`, `SITE_MANAGER`, `PARTNER_REQUESTER`. Self-decisions: `SELF_DECIDING_ROLES` decide their own requests through a grant of that role on the request, with session MFA (`authorize_self_decision`, audit `self_decided: true`); other reviewers only where the procurement branch sets `allow_self_approval`.
- Out of scope → **404**; in scope without capability → **403**; unsupported method → **405**.
- Validity is half-open (`valid_from ≤ now < valid_until`, database clock); inactive companies/branches drop out of every scope.
- Never authorize with `is_superuser` (platform operators only); group admins never modify staff/superusers.
- Scope-defining changes (company/branch `is_active`, `managed_by`, project branches/status) lock `AccessState` `FOR UPDATE`, and changes to a user's authority lock that `User` `FOR NO KEY UPDATE`, before `authorize_in_txn`; database triggers (`access.0002`, `accounts.0003`) bump `org_generation` / `authz_generation`. Memberships and assignments are revoked, never deleted (trigger).
- Views check with `require()` / `@require_capability` / `@mutating` (POST only) or the matching mixins; `{% can %}` only hides UI. Privileged roles need session MFA after `privilege_elevated_at` on every page and in `authorize_in_txn`.
- Every URL **and method** gets rows in `tests/access/test_acceptance_matrix.py`, including redaction and revoked-access cases.
- Project receiving (Q44, ADR-0028): every business role posts receipts at the worksite of a project in its membership's scope, whoever requested the goods. `receipt.view`/`receipt.post` are `Reach.SITE` (○ site) for site managers, technicians and partners (documents only through their project; no branch row, warehouse or order), and for these `SITE_CAPABILITIES` the branch roles' grants also reach their projects' worksite documents. Warehouse receiving and `receipt.void` stay with the order's branch; a project receiver without `po.view` names only the project's lines and allocations. Screens (M9.2): the project page offers "Receive materials" (to the project's expected deliveries, then the receipt form); `selectors.receives_by_order(ctx)` is false for who holds only site grants, who is never offered the order search (the receipts list and the project list lead to the projects, the form's breadcrumb returns to the project).
- Master data (catalog, units, suppliers) is installation-wide: models use `InstallationQuerySet`, a grant reaches all of it or none, and what a role sees is decided by the capability (`catalog.view` every role, `supplier.view` only group admins, material managers, engineers and warehouse operators; suppliers never reach technicians, partners or site managers outside the expected-deliveries projection). Materials and suppliers are deactivated, never deleted; a material's `reference` is fixed. Imports (`manage import_*`) and `seed_demo` call the same services as the screens, as an `OperatorPrincipal` per capability; a file with any error writes nothing.

**Quantities** (plan §4.5, I1–I12):

- `Decimal(12,3)` quantities, `Decimal(14,4)` prices, never float. Received, pending, draft-reserved, delivered, committed, awaiting-handover, to-purchase and outstanding are **derived**, never stored.
- Transition eligibility uses state-independent predicates only (plan §4.9).
- Pending is a waterfall over open allocations in attribution order, capped by what the line can still receive; draft allocations reserve demand.
- committed = max(D, R) + P + Q ≤ approved. Any change to an input (incl. priority/needed-by) reconciles the whole component: discover, lock L2–L5, verify, apply, fixpoint. Cuts target effective pending. Issuing a draft revalidates.
- Worksite receipts attribute by allocation ceiling; every attribution is capped by A − R (and A − D on site); excess is surplus. R ≤ A and D ≤ A always.
- `allocation.qty` grows only via authorized allocate/increase (rule C5), shrinks only via audited trims ≥ attributed. Receipts split into `ReceiptAttribution` rows.
- Closures record `closed_short_source` (`LINE`/`REQUEST`); request reopen clears only `REQUEST`.
- Composite FK `(material_id, unit_id) → Material(id, unit_id)`; never change a referenced material's unit.

**Writes** (plan §4.7–4.8). Each mutating service, in order: `transaction.atomic()` + `lock_timeout` → `authorize_in_txn(principal, …)` (full check every time, never skipped on unchanged generations) → `IdempotencyRecord` (signed key, 24 h, bound to actor + operation + payload hash; replay re-authorizes; same key + other payload → 409) → locks in canonical order (request headers → request lines → PO headers → their outbox rows → PO lines → receipts → handovers → `StorageQuota` → `DocumentSequence`; header before children; discover → lock → verify) → recompute aggregates → validate invariants and C1–C10 → write → reconcile → `audit.record` + `events.publish`. Retry deadlocks only through the shared wrapper.

- Editing by state: plan §4.4 as amended by ADR-0014. A requester changes material/unit/quantity only in `DRAFT`; `request.edit` holders edit lines in `SUBMITTED` and `APPROVED` within the ledger floors, as revisions against the immutable as-submitted copy (M7b.3); back to `DRAFT` clears decisions. Issued POs change only via audited amendments; snapshots never rewritten.
- Posted receipts/handovers are immutable: void (with reason) and re-enter; a void can reopen documents. `DIRECT_RECEIPT` handovers are voided only through their receipt.
- State changes only via services checked against `ALLOWED_TRANSITIONS`; no FSM library.

**Identifiers.** UUIDv7 primary keys; users see `DocumentSequence` numbers. Audit table is append-only (trigger), and so are a request's as-submitted copies and line revisions (`material_requests.0004`). Apps are `material_requests` and `handovers`.

## Security

- **Browser:** the display preferences are one `__Host-ui` cookie written only by `/ui/preferences/` (no script writes a cookie; allowlisted values, never reflected, never an input to authorization; ADR-0027); strict CSP (no inline script/style/handlers); htmx via `<meta name="htmx-config">` with `historyCacheSize: 0`, CSRF in `hx-headers` on `<body>`; authenticated responses `Cache-Control: no-store, private`; pre-auth pages also `no-store`; a URL that carries a token is `Referrer-Policy: no-referrer` and redirects to a token-less URL (pages with a form stay `same-origin`: `no-referrer` makes browsers send `Origin: null` on POST, which CSRF refuses).
- **Banned** outside the `scripts/check_access_rules.py` allowlist: `|safe`, `mark_safe`, `csrf_exempt` (only the upload entry point), `.raw()`, `.extra()`. Mutating views are POST-only; GET/HEAD never call a service. The script also parses the code for the plan §3.6 guardrails: scoped managers in views/forms/template tags, `is_superuser` outside `apps/access`, a public service that writes without reaching `authorize_in_txn` (a helper that writes for an authorized caller is private, `_name`), a service reached from a non-POST-only view, a plain `ModelAdmin`, token/system/operator principals outside `CONSTRUCTOR_MODULES`, SMTP or `send_mail` outside the outbox worker. Only GET, HEAD and POST reach a view (`AllowedMethodsMiddleware`, 405 otherwise).
- **Admin:** every `ModelAdmin` on the service-backed base; access and document models read-only; no deletes; a list filters only on its `list_filter`/`date_hierarchy` fields (`lookup_allowed`), so a hidden column (`exclude`) is never queryable.
- **Exposure:** prices only with `price.view`; partners never see prices, suppliers or others' requests; site managers get only expected-deliveries fields (plan §3.4).
- **Sessions:** absolute 12 h privileged / 14 d others, idle 30 min / 2 h, all from env (`apps.accounts.sessions`); a request a page sends by itself must not count as activity (`@session_passive`, on any new poll); anyone signed in lists and ends their own sessions (`OWN_ACCOUNT` in `authorize_in_txn`: no role's capability; session MFA if privileged).
- **HSTS:** opt-in in production, one env switch each (`DJANGO_HSTS_SECONDS`, `_INCLUDE_SUBDOMAINS`, `_PRELOAD`), never automatic; `web` warns at startup while one is off, a deploy check never fails on it (X3).
- **Auth:** django-allauth ≥ 65.20.1 (CI floor), admin login through allauth; a password or second factor that changes tells its owner (`ACCOUNT_EMAIL_NOTIFICATIONS`, through the outbox); allauth email views off (admin-initiated email change: new address confirms, old can cancel within 24 h, authority re-checked); reset never logs in, no login-by-code; `__Host-` cookies; reset tokens re-validated under the user-row lock (single use, 1 h); "MFA required" = this session passed MFA; MFA secrets encrypted with `MFA_ENCRYPTION_KEYS`; rate limits on `SecurityDatabaseCache` (429 when full); `ALLAUTH_TRUSTED_PROXY_COUNT=1`.
- **Accounts:** offboarding revokes the user's pending invitations and email changes and those they initiated; token redemption locks target and initiator users (id order) then the token, re-checks authority, never changes an active account's credentials; tokens 32 random bytes, hash stored, constant-time compare; first admin only via `manage bootstrap_admin`; `createsuperuser` disabled.
- **Logging:** no secrets, tokens, passwords or needless personal data; token URLs, query strings, `Referer`, `HX-Current-URL` and Caddy's response `Location` redacted at every layer (sentinel test); security events go to `gmat.security` (`apps.accounts.security_log`: account ids, never an address typed); every line of a request names the signed-in account (`user`). A deviation from a rule is an entry of the exception register in `docs/security.md` (owner, review date ≤ 90 days), accepted in a PR.
- **Attachments** (plan §5, ADR-0015): every operation checked against the parent (`apps.attachments.parents`); admission before the body is read (the one `csrf_exempt`, inner `csrf_protect`), quota/slots/2-in-processing under the L8 quota lock; every file scanned by `clamd` before anything else, and no verdict means not stored (503); images decoded only in the killable, rlimited child, in its own container in production (`gmat.E022` refuses production without both sockets), and what comes back must be WebP; files never served from the volume, only through the authorised download (`attachment`, `nosniff`, sandbox CSP); physical deletion only in the worker's purge while it holds `gmat:media-backup`.
- **Email:** never SMTP in a request; all mail via `EmailOutbox` + `worker` (plan §5): `MAILERS["default"]` is the outbox backend (allauth's mail too), business code queues with `apps.notifications.outbox` inside its transaction, only `apps.notifications.worker` sends (`MAILERS["outbound"]`); recipients stored as user ids, eligibility re-checked at claim; claims commit before I/O; dispatches lock their order first (L4 → L4b, the purchasing app registers a `DispatchSource`); a restore quarantines everything unsettled and a human releases it (plan §9, `manage outbox_quarantine`); PO cancel cancels unsent dispatches in the same transaction and keeps the `PO_CANCELLATION` obligation; outcome updates conditional on attempt id; worker idle while `flags/worker.paused` exists or `OUTBOUND_EMAIL=off`; security mail sealed with `OUTBOX_ENCRYPTION_KEYS`, wiped after send or expiry; `AMBIGUOUS` dispatches never auto-resent. Django forbids `EMAIL_*` settings next to `MAILERS`: the per-operation timeout is `OUTBOX_SMTP_TIMEOUT`.
- **Other:** explicit timeout on every outbound call; production settings fail closed and `manage.py check --deploy` has zero warnings.
- **Containers:** non-root uid 1000 (the `decoder` uid 1001, `clamd`/`freshclam` their image's uid 100, `db` its image's uid 70, no capability, so `gosu` never runs), read-only root fs; only Caddy publishes ports; only Caddy and `web` share `edge`; each DB client (`web`, `worker`, `backup`, `migrate`) has its own internal network; DB never published; what parses uploads (`clamd`, `decoder`) has no network and no secret, and `web` reaches it through a unix socket on a volume only the two mount, read-only on `web`'s side (ADR-0015).
- **Backups:** append-only offsite credentials on the VPS; pruning from the maintainer's machine (`--keep-within 90d`, `scripts/offsite_prune.py`, which refuses forged snapshots); dumps exclude sessions/cache; restore drills offline.
- **Deploys and restores:** nothing runs without its signature checked and no flag skips one; what a release states about its migrations is read only from the signed manifest, never the notes, and the image packages are public, so the VPS holds no token (ADR-0017); both gates on until the commit point; after any restore `post-restore-reconcile` runs before they open, and what could hand over an account (an email change, a removed second factor) waits for a human (ADR-0016). A new audit action that takes away access or a credential needs a handler in `apps.recovery.replay.HANDLERS`, and a new family of them in `ops/failed-state.sql`.
- **Supply chain:** deps via `pyproject.toml` + `uv.lock`; images and Actions pinned by digest/SHA; Trivy without `--ignore-unfixed`; exceptions in `.trivyignore.yaml` with statement and ≤ 90-day expiry, human-approved.

## Stack

Python 3.14 · Django 6.1 (6.2 LTS = B1) · PostgreSQL 18 + psycopg 3 · htmx **2.x** vendored + django-htmx · Tailwind v4 standalone CLI · Chart.js 4 (UMD, vendored, loaded only on pages that draw a chart), Inter and a Lucide icon subset, all vendored under `static/vendor/` (ADR-0027) · django-allauth (account + mfa + usersessions) · Gunicorn `gthread`, WhiteNoise, Caddy · ClamAV (`clamd` + `freshclam`, x86-64 only, ADR-0015) · Docker Compose, uv; axe-core in the optional `e2e` group only (the accessibility gate, nothing shipped). No Redis, Celery, JS framework, Node tooling or API layer without an approved plan change.

## Layout

`config/` (settings `base`/`dev`/`test`/`prod`/`build`, `env.py` fail-closed helpers, `logging.py` redaction, urls/wsgi/asgi) · `apps/<app>/` (`core`: `BaseModel`, security cache, checks, middleware, admin base classes, `sequences` (`next_number`), `idempotency`, `locking` (L0-L9, `LockOrder`, `run_in_transaction`/`@transactional`, advisory locks), `events`, `fields` (quantity/price presets), `migration_ops` (composite FKs; `on_update="CASCADE"` for a denormalized key children follow), `commands` (`OperatorCommand`; `also_capabilities` + `principal_for` for a command that spans domains), `tabular` (CSV/XLSX reader), `imports` (`ImportCommand`: report, one transaction per file, `--dry-run`), `demo` + `manage seed_demo`, `changes` (`apply_changes`), `db` (`db_now`, `db_clock`), `stats` (M8b.5: `Calendar` of a period's weeks, `weekly`/`weekly_by`/`weekly_aggregate` counted in SQL by `TruncWeek` in `TIME_ZONE`, `Median`/`median_duration`, `top`), `forms` (`IdempotentForm`, `ValidityForm`, service errors), `responses` (409/400 answers, `perform`/`invalid` for a POST-only action's flash and redirect; M8b.3's dialog contract: `go` (redirect, or 204 + `HX-Redirect` to htmx), `Dialog` (a form shown again in its dialog: 422 with its errors), the 409 fragment `components/dialog_problem.html`, `varies`), `dialogs` (M8b.4: `ActionDialog`, one object that says what a page's action dialog shows (title, consequences, warning, form, where it posts, tone) and is drawn by `components/action_dialog.html` and rebuilt around the bound form by the POST view (`spec.dialog()`, so the 422 shows the same markup); `lazy` answers the fragment of a row's shared lazy dialog to htmx and `layouts/dialog_page.html` otherwise (a GET-only URL, matrix rows with their htmx variants); a page with rows per line, allocation or dispatch keys its dialog and field ids by them; ## Testing

- PostgreSQL only, never SQLite. Markers: default, `integration`, `live`, `e2e`, `rehearsal`, `serial`; `--strict-markers`.
- CI runs the tests in four parallel shards behind the required `test` gate (ADR-0025). Before writing or changing a test, follow `tests/CLAUDE.md`: `serial` for anything that depends on wall-clock time, fixed `ids=` for values made at import time, nothing shared between workers, `--dist load` only.
- Coverage ≥ 90 % overall; 100 % for `apps/access`, every `services.py` and `selectors.py` (or such a package). CI sends `coverage.xml` to Codecov and Codacy after a green `test`; `source_pkgs` keeps its paths relative to the repository's root.
- Each service: allowed, denied and revoked roles, invariants, integrity rules, transitions; concurrency-sensitive ones add a threaded test in `tests/integration/`.
- A service that changes a ledger input (plan §4.5) becomes an operation of the state machine (`tests/integration/test_ledger_machine.py`, also in its tour); a new invariant or integrity rule gets a check in `tests/invariants.py` and a case in `test_invariant_checker.py` showing the check notices it broken.
- Use the shared A/B/C fixture (plan §8.1, `tests/org.py`: fixtures `org`, `people`, `member`; `Sentinel`) with its sentinels; leak assertions are per projection (plan §8.2). A step that adds a supplier, price or quantity model seeds its sentinels there.
- A new URL needs its row in `ROUTES` (`tests/access/test_acceptance_matrix.py`): GET, HEAD and POST for every actor of `tests/access/matrix.py`, one `Route` per object position, and the sentinels its responses may show.

## Conventions

- **Lists:** every list view pages through `apps.core.listing` (`paginate` + `render_list`, the toolbar/summary/pager components, filters from selectors; page size, sort and page live in the URL only). Bounded document lists are the exceptions (plan Q43): lines of a request, order, receipt or handover, the attachments panel, dashboard panels, the catalog picker. A list view that bypasses it needs a reason in the PR. A page with several lists (a project's assignments, a person's roles, shared projects and invitations, the purchasing worklist's drafts and ordered-for-nobody) gives each section a `ListScope` (`assignments_page`, `drafts_page`, …), a prefixed filter form (`assignments-state`) and `list_toolbar.html` with `scoped=True` and `select=` (htmx takes the section out of the full page; no extra URL), inside a `data-list-section`; ticks of the worklist builder count for the page shown (plan Q41). **Every list reads only what it shows:** the database pages it (`LIMIT`), never Python after loading the whole set. A list whose rows are worked out from the ledger (the purchasing worklist and its ordered-for-nobody section, a project's materials, its expected deliveries) is read from a cursor instead (`cursor_page`, `CursorPage`, `components/cursor_pagination.html`; plan Q40): a source's `seek(cursor, n)` reads the next `n` candidate keys from the database in the list's order (`seek_after`: the order's fields annotated, never NULL, primary key last; the cursor's anchor read without the list's filters, so a row that left the list still marks its place), and its `window` works out the rows of that stretch only, so a page costs the page, not the backlog; its order and filters are SQL-able (a derived quantity can drop rows in the `window`, never order them); First / Previous / Next, no total, and the dashboard counts built the same way stop at "99+" (`head`). Such a list must give the rows of the eager `to_purchase` / `unallocated_on_order` / `expected_deliveries` page after page (tested on the volume dataset). **Budget (M7d.4):** every list answers in at most 300 ms of server time on `tests/volume.py`'s dataset (100k audit events, 20k materials, 10k requests with 50k lines, 5k orders, 5k receipts, 2k handovers) and costs the same number of queries at 10 and at 100 rows (`tests/integration/test_list_volume.py`, best of 5; a new list or panel gets a `Screen` there). A list whose every row is a heavy card (My requests, the worklist) caps its sizes with `ListScope(max_per_page=…)` (50, the worklist 25); `{% chip %}` (`ui_tags`) replaces the chip include on rows drawn by the hundred. `templates/django/forms/widgets/select.html` writes a select's options in place (same markup as Django's, no include per option: a filter with hundreds of projects or suppliers).
- **Dialogs (M8b.3, ADR-0027):** `templates/components/dialog.html`, a native `<dialog>` (bottom sheet on a phone). *Inline* for a small form on a bounded page (a partial of the page, opened by `commandfor`/`command="show-modal"`); *lazy* for a larger form or a row of a paged list (a link to the form's GET page with `hx-get`, `hx-target="#<id>-content"`, `data-dialog-open`; the view answers its `{% partialdef %}` to htmx, the page otherwise, `Vary: HX-Request`). The form posts with `hx-post` and `hx-disabled-elt` on its `<fieldset class="dialog-foot" data-dialog-actions>`, `novalidate`, `components/error_summary.html` on top; its view passes a `Dialog` to `perform`/`invalid` and redirects with `go`. A dialog never opens another. Pilots: void a receipt, change a request line.
- **README:** written for someone arriving at the repository: what the application does, who uses it, how to try it. It is for any company, not one trade. Never the plan, its phases or internal ids (`M8`, `Q23`, `X3`); those belong in `CHANGELOG.md`, the ADRs and `docs/security.md`.
- English code, comments and commits; UI strings via gettext; default language `es`, also `en`, `fr`.
- **Function size (Codacy, lizard):** every function or method you write or change has a cyclomatic complexity of at most **10** and at most **8 parameters** (`self`/`cls` and keyword-only ones count). Split branches into small helpers or a lookup table, and group related arguments in a frozen dataclass (as `HeaderAmendment`, `LineAmendment`). Nested functions count on their own. Check with the lizard command above before pushing; none is over the limit in `apps`, `config` or `scripts`, and an existing one in `tests` is fixed when it is next changed.
- **File size (Codacy):** a file of `apps`, `config` or `scripts` stays under **500** lines of code (lizard's NLOC). Split a larger one into a package whose `__init__` keeps the docstring and re-exports the public names (`apps/accounts/services/`, `apps/purchasing/selectors/`): a submodule is named unlike anything it exports, and imports its siblings absolutely, which is what the access rules follow. A test patches a helper in the module that calls it.
- Tests never compare a string translated at import time with one rendered during the test: the active language is per thread and requests change it. Translate inside the test (`gettext_lazy`, or `translation.override`).
- **UI rules (M8b, ADR-0027):** every page starts with `components/page_header.html`; no `style` attribute, inline script or handler (`test_template_rules`); a new action form opens in a dialog (the contract above), never a page of its own unless it needs one to work without JavaScript; chart data travels as escaped JSON in the canvas's `data-chart` attribute, not `json_script` (htmx removes `<script>` from swapped fragments, ADR-0027); every chart has its data table beside it; a menu or sheet that is a popover closes when the keyboard leaves it (`app.js`); a new screen passes `test_accessibility` (axe: no serious or critical finding, both schemes, 360 px) and keeps the keyboard walk true (`ACCESSIBILITY.md`, `test_keyboard`); an `aria-label` goes only on an element whose role allows it (a disabled pagination link is `role="link"`); a `<dl>` holds only `<div>`s of `dt`/`dd`.
- Mobile-first templates (check at 360 px): unprefixed classes are the phone layout, wider screens only add (min-width and container queries), no `max-*` variant shapes a layout; colours are only tokens from `static/src/app.css` (an edit to a token runs `scripts/check_contrast.py`); every view follows `docs/design/` (ADR-0027); page template + `{% partialdef %}` partials; shared pieces are includes under `templates/components/`. After editing templates rebuild the CSS (dev compose runs Tailwind in watch mode), and after adding strings run `makemessages -l es -l en -l fr` and `compilemessages`.
- Migrations expand/contract and reversible (or flagged in PR and release notes); CI checks.
