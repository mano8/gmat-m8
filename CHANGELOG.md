### Added

- `scripts/check_access_rules.py`, a static guard for banned constructs and forbidden workflow triggers.
- Dependency management with uv (`pyproject.toml`, universal `uv.lock`) and tool configuration for ruff, mypy, pytest and coverage.
- Repository hygiene files, pre-commit configuration, agent deny rules, architecture decision records (ADR-0001 to ADR-0013) and a pull-request template.
- CI pipeline (`.github/workflows/ci.yaml`): `lint`, `typecheck`, `security`, `test`, `trivy-image` and `secret-scan`, with a PostgreSQL 18 service, coverage gates, migration reversibility, Trivy policy without `--ignore-unfixed` and `.trivyignore.yaml` for documented, expiring exceptions.
- Guards `scripts/check_security_floors.py`, `check_trivyignore.py`, `check_coverage_gates.py` and `check_migrations_reversible.py`, workflow policy tests and a monthly Dependabot configuration.
- Security baseline ([docs/security.md](docs/security.md)):
  - django-allauth with email login, closed sign-up, no email-management, email-confirmation or login-by-code views, POST-only logout, no account enumeration, and a password reset that never logs in and is redeemed under the user-row lock;
  - MFA (TOTP, recovery codes, optional passkeys) with secrets encrypted by `MFA_ENCRYPTION_KEYS`, a session-level MFA check that only counts the user's own authenticators, and pending logins discarded at each new login;
  - session epochs with a database trigger (password, email and deactivation end every session; counters never decrease) and session lifetimes of 12 hours for privileged accounts and 14 days for the others;
  - admin login through allauth with session MFA, `ServiceBackedModelAdmin` and read-only admins for accounts;
  - `SecurityDatabaseCache` for rate limits: atomic, never evicts live entries, JSON only, 429 when full;
  - CSP, `Permissions-Policy`, `__Host-` cookies, `no-store` for authenticated and token pages, `Clear-Site-Data` on logout, request ids;
  - JSON logging with token redaction on every handler, a redacting error-report filter and an error-tracker scrubber;
  - fail-closed system checks (`gmat.E001`–`gmat.E020`).

- **The server must be x86-64**, and needs about 1 GB more memory (ADR-0015). `web`'s limit is 1 GiB; the `decoder` has its own.
- Caddy 2.11.9, and the newest PostgreSQL 18 and Python 3.14 digests; the findings of the first two had never been reported: the nightly scan failed before scanning anything.
- The application image no longer ships SQLite (PostgreSQL only), which also removes its findings.
- After a restore, an email change or a removed second factor newer than the backup is no longer applied by itself: the account stays suspended until an operator accepts or rejects it (`manage confirm_account --email-change`, `--factor-removal`; ADR-0016).
- The database container runs as its image's `postgres` user from the start, with no capability, so `gosu` never runs.
- The deploy tooling reads what a release states about its migrations only from the signed manifest, never from the unsigned release notes (ADR-0017).
- The image packages are public and the VPS holds no GitHub token (ADR-0017).

### Fixed

- The VPS runbook asked for a fine-grained token to pull the images, which GHCR refuses after a successful login.
- The admin's lists accept only the filters they offer: a query-string lookup on a hidden column (a password hash, a token hash, an MFA secret, a price) could be read back from the result count. The audit admin no longer shows event payloads or client addresses (M8.3).
- An over-receipt at a worksite no longer tells a site manager how much the order line holds for other projects, through the message or the order of the refusals (M8.3).
- Removing a passkey keeps a privileged account's last second factor, as deactivating its TOTP already did (M8.3).
- A token link over its rate limit is answered by the token-less page, so the token never stays in the address bar (M8.3).
- Caddy's logs drop the response's `Location`, which carried the token of a link opened without its trailing slash; PostgreSQL logs no slow statements with their values; role passwords stay off the `psql` command line (M8.3).
- A checkout without Playwright no longer fails at collection: pytest entered `tests/e2e` and imported its `conftest.py` (M8.2).
- The nightly image scan verifies the signed manifest of the latest published release before using its digests (M8.3).
- The local agent guard denies `gh api` writes made through fields or a body, and tag pushes by refspec (M8.3).
- A supplier dispatch held in quarantine can be confirmed or sent again from the order page like an ambiguous one, and a cancellation owes the supplier a notice for it (M8.4).
- Tables that collapse to cards on a phone wrap a long identifier instead of widening the page (the audit list overflowed a 360 px screen by 14 px; found by the browser suite, M8.2).
- Purchasing review findings (after M5): the builder no longer offers request lines another draft reserved in full meanwhile (they are left out and reported); `issue` re-checks that each line's material is still active and that every live allocation still meets C5, C6 and S9 (project active, branches active); a line closed short shows its received quantity, marked closed, on the printable page and in the supplier email, and the line total follows it; an amendment that closes the order is still sent to the supplier (only a cancelled order refuses it); a dispatch queued again after an ambiguous attempt still owes the cancellation notice when the order is cancelled; the order page says a notice will follow only while a dispatch is being sent and none is queued yet; `trim_to_attributed` no longer reads each allocation's attributed quantity twice; the `Message-ID` domain helper is shared (`notifications.outbox.sender_domain`).
- The passkey list (`/accounts/2fa/webauthn/`) failed with a server error for every signed-in user: allauth's template loads `humanize`, which was not installed (found by the acceptance matrix).
